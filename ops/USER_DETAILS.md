# 用户详情与人工退款核查

用户列表的用户名/「用户详情」、消费/任务日志的用户入口和兑换码的兑换用户，共用只读详情窗口。

## 如何维护与核查

1. 查看用户注册、最后登录、邀请人、分组和管理员备注。备注继续通过现有编辑入口维护，不在详情里绕过原权限。
2. 查看充值订单的原始金额、状态、支付来源、订单号和订单额度快照。仅成功订单表示入账，待支付订单不是已到账额度。历史没有保存币种或入账快照的项目显示未记录。
3. 查看兑换和签到赠金。注册、邀请及管理员调整的旧记录在系统/管理日志中核对；不能用现在的赠金设置倒推用户过去获得的额度。
4. 查看消费、错误和额度返还日志，按类型筛选、分页，再跳转完整日志核查请求。额度返还不是现金退款。
5. 联系支付平台核对实际收款和退款情况，按本站退款政策人工处理。当前详情只读，不触发支付退款或修改用户额度。

混合钱包的总余额不是剩余充值本金。缺少资金批次/赠金来源核销时，系统不能可靠拆出可退现金；不以「余额×展示汇率」作为退款公式。建议后续独立设计赠金批次、消费分摊、退款单与支付回调幂等，再考虑自动退款。

## API与权限

`GET /api/user/:id/insight?section=overview|topups|redemptions|checkins|logs&p=1&page_size=10&log_type=0`

仅管理员访问，沿用目标角色限制，普通管理员不能查看同级/更高权限用户。分页最大50。资料、订单和赠金读主数据库，日志读独立LOG_DB。显式白名单DTO不返回密码、用户设置、API Key、兑换码密钥、IP、请求正文或原始诊断metadata。

旧类型日志的Quota字段不一定记录额度变动量。概览不合计未知赠金，系统/人工调整等日志的金额栏显示未记录；只有消费和API额度返还等有金额语义的记录显示数字。
