# CPA v8.0.43

2026-10-26（Asia/Shanghai）生产 CPA 从 v8.0.41 升级至官方稳定版 v8.0.43。只切换 CPA 程序并重启 `relay-native-cpa`；New API、CPAMP、门户、Nginx 和生产配置未重启或修改。

## 官方变更

v8.0.42 修复插件仓库索引与 packfile 损坏处理、插件跨域重定向凭据头清理、`count_tokens` 返回值、`Retry-After` 传递和请求日志路径遍历。v8.0.43 继续修复 Codex duplex WebSocket 与模型绑定、重新授权隔离、凭据快照绑定及失败刷新后的轮换恢复，并修复 Gemini `$ref/allOf`、Claude OAuth MCP alias、流关闭与取消、重试和静态分析问题。

## 候选与生产验收

隔离候选使用合成账号和本地模拟上游，39 项检查全部通过，覆盖三个已启用插件加载、两组 Key Router 分池、无可用账号时返回 503 且不串池、Responses/SSE/Chat/compact、并发准入和取消释放、凭据编辑及配置 ETag。候选未读取生产 OAuth 文件，也未发起真实上游请求。

生产切换前等待并发归零，保存了短期程序、配置和认证目录回滚副本；原子替换后 CPA 在 5.32 秒内恢复健康。5 份认证文件、账号池、并发上限 3、Codex 流启动缓冲和受保护控制文件均保持不变。实际生请求返回 HTTP 200/completed（输入 319、输出 5 Token），CPAMP 记录新增并包含账号归属；collector running、dead letters 为 0，SQLite `quick_check=ok`。

随后进行了约 307 秒健康观察，11 个采样全部通过，CPAMP 事件从 24047 增至 24061；CPA、CPAMP、New API、门户和 Nginx 全部保持 active，未见 panic、fatal 或插件加载错误。

验收后删除候选目录、官方安装包、临时脚本和短期回滚副本，释放约 263 MB。保留脱敏验收记录、长期统计库、`data.key`、生产 OAuth 文件和生产配置。
