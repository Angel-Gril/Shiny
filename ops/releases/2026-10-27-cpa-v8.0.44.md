# CPA v8.0.44

2026-10-27（Asia/Shanghai）生产 CPA 从 v8.0.43 升级至官方稳定版 v8.0.44。只切换 CPA 程序并重启 `relay-native-cpa`；New API、CPAMP、门户、Nginx 和生产配置未重启或修改。

## 为什么升级

本版本包含与本站当前流量和观测链路直接相关的修复：

- 流在首个 chunk 前关闭时正确报告取消，减少假成功或悬挂请求；
- Scheduler 选中账号与 UsageRecord 共用 per-selection ID，改善 CPAMP 账号归属；
- Codex 上下游全链路压缩和 commentary 历史签名恢复，适合长上下文请求；
- 明确允许 CORS 预检中的 Authorization；
- 插件请求体按 schema 选择性传递，降低插件开销；
- 截断的 HTTP 200 流不再错误触发账号冷却和故障转移；
- 修复 Interactions 终止流的 `[DONE]`、工具限制和发现协议相关问题。

## 验收

隔离候选 39 项全部通过，覆盖插件加载、两组 Key Router 分池、无可用账号时返回 503 且不串池、Responses/SSE/Chat/compact、并发准入和取消释放、凭据编辑及配置 ETag。候选使用合成账号，没有读取生产认证文件。

生产切换前等待并发归零，原子替换后 CPA 在 1.909 秒内恢复健康。5 份认证文件、两个账号池、每账号并发 3、Codex 流启动缓冲和受保护控制文件均保持不变；New API、CPAMP、门户和 Nginx PID 未变化。

最小真实 Responses 请求返回 HTTP 200/completed（输入 319、输出 5 Token），CPAMP 事件新增并包含账号归属字段；collector running、dead letters 为 0、SQLite `quick_check=ok`。随后进行了约 307 秒健康观察，11 个采样全部通过，事件从 24577 增至 24618。

验收后删除候选目录、官方安装包、临时脚本和短期回滚副本，释放约 240 MB。长期统计库、`data.key`、生产 OAuth 文件和生产配置保持原位。

## 插件与边界

- Key Router v0.5.0，优先级 100。
- CPA Account Concurrency v0.1.8，优先级 50，每账号最大并发 3。
- Codex Candy Eval v0.4.3，启用。
- Quota Monitor v0.2.2，启用。

本次升级没有新增 Scheduler，也没有改变 Key Router 的严格分池边界；选中的账号达到并发上限时，CPA 仍不会因此自动跨池换号。
