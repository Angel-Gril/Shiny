## 已有配置与实际修复

站长提供的公开 Site key 已与主站设置一致，Secret 已保存且人机验证开启。
本轮读取并遵循 [Cloudflare existing-widget 流程](https://developers.cloudflare.com/turnstile/spin/prompt.md)，
复用已保存 Secret，没有新建 widget、恢复/轮换密钥或改 Cloudflare 账户配置。
Secret 的 canonical dummy-token 探针返回 `invalid-input-response`，不含 `invalid-input-secret`，
只用于确认已有密钥有效，不以此代替真实用户验证。

初次浏览器检查中，主站登录、注册和找回密码的真实 Cloudflare 组件均可加载；
不是 Site key 缺失。修复代码中能观察到的缺口：

- 组件过期、超时和错误主动清空表单 token，脚本加载/渲染失败提供翻译后的重试控件。
- 发送注册验证码、注册和找回密码的每次提交结果后换新 widget/token，失败不复用已消费值；
  登录保持原有提交后刷新，签到不因错误回调无限重建。
- 固定 action：登录 `login`、注册/发送注册邮件 `signup`、找回密码 `password_reset`、签到 `checkin`。
- 服务端 canonical Siteverify 设置 10 秒超时、拒绝重定向；校验 success、action、
  `ServerAddress` 的精确 hostname。网络/解析/配置错误不放行，也不向客户端回显底层敏感异常。
- 成功验证后原子记录五分钟 token SHA256，Redis 跨节点，Redis 不可用时拒绝；
  无 Redis 的单进程使用有界内存。Cloudflare 自身重放检测存在最终一致性，不作为唯一防线。
- 当前客户端通过 `CF-Turnstile-Response` 请求头提交，不将 token 放在 URL；保留旧 query 传输兼容，
  但旧 widget 没有 action 的已打开页面应刷新以加载新代码。

原登录、注册、邮件验证、重置、签到业务 handler、账户权限、会话、限流、计费和审计规则保持原行为。
没有增加 schema 或重新设置生产密钥。参照 OWASP Authentication、Session Management、Forgot Password
Cheat Sheets 核对服务端 gate 和单次凭证边界；不宣称完整 ASVS 合规审计。
