# 渠道重试与号池故障

New API 选择渠道，CPA 的 Key Router 在该渠道密钥授权的账号池内选择账号。CPA 的 `auth_unavailable` 表示该池没有可用账号，不代表另一个 New API 渠道也不可用。

2026-10-17 22:22（北京时间）的故障日志出现 `retry: 9->9`：会话优先绑定低优先级渠道后，旧选择器按重试次数选优先级，重复选中已经失败的渠道。当前配置已是 `prefer` 和 `RetryTimes=1`，此问题不能通过再次修改这两个值解决。

修复后：仅在现有重试策略允许的情况下，优先从当前分组、模型和过滤条件允许的未尝试渠道中，按优先级与权重选择。若没有其他候选，沿用原有同渠道重试预算，不无限重试。显式渠道绑定与严格会话保持原有约束；不额外放行已经禁止重放的错误。

保持备用渠道启用且模型/分组匹配。被管理员禁用的渠道不参与切换；不能因为需要备用而自动恢复管理员已禁用的渠道。两个密钥若最终绑定同一批耗尽账号，切换渠道也无法恢复额度。

生产诊断只记录脱敏路由轨迹和错误类别，禁止提交账号凭据、用户请求正文与原始日志。回归覆盖 SQLite、MySQL、PostgreSQL 的缓存开关、不同/相同优先级、禁用渠道、分组隔离、显式绑定和严格会话。
