# Shiny 门户内容服务

2026-10-16 已上线 https://shinyapi.com/ 。门户沿用独立发布方式，新增教程、下载与内容管理，不修改 New API/CPA 推理代码。

## 页面与管理

- 首页 `/`，教程 `/docs/`，下载 `/downloads/`，公告 `/announcements/`。
- 内容管理 `/site-admin/`：使用现有 Shiny 超级管理员账号登录。普通用户和只读 PAT 无发布权限。
- 编辑后先「保存草稿」，再「发布到网站」。公共内容缓存约 30 秒。
- 文章支持完整 Markdown 原文保存及导出、GFM 表格/列表/链接/图片、多代码块和复制；支持单篇、多篇与文件夹导入，每篇最大 1 MB，每批最多 100 篇。导入先预览和保存草稿，再发布。内容库单次保存总 JSON 仍限 2 MB、最多 200 篇文章。
- 图片可在正文编辑器直接上传插入，草稿预览通过管理员鉴权获取；未发布图片不公开。附件支持 PDF/DOCX/MD/JSON/ZIP/PNG/JPG/WebP，单文件最大 20 MB。
- 资源可使用官方外链或上传文件；上传附件随关联资源发布后才可公开下载。当前页面不自动将 DOCX/PDF 转为网页。
- 公告复用 New API 的原有公告设置；首页标题、导航、文章与下载条目由门户管理。模型价格继续由 New API 管理。
- 已发布版本可恢复为草稿，确认后再次发布。版本恢复不会删除附件，避免回滚时丢失引用。
- 教程列表支持删除未发布草稿；已发布教程可「从草稿移除」，再次发布后才下线。下线前可在「待下线教程」恢复到草稿。关联下载资源的教程需先更换或移除资源引用；删除不会清理物理附件和发布历史。
- 存储设置 `/site-admin/?tab=storage` 支持 R2 S3 凭据的只写保存；R2 单文件默认 10 GB，可设置 512–102400 MB。超过 64 MB 自动分片，支持失败重试、暂停和刷新后续传；本地附件仍为 20 MB。

## 与 New API 的接口边界

服务向固定 loopback New API 调用 `/api/user/self` 和 session-only `/api/user/sessions` 校验浏览器管理员身份，向 `/api/status` 读取公告。没有复制 New API JWT 签名秘密或另建管理员密码。

浏览器只在内存保存短期 access token，使用已有 `/api/user/auth/refresh` 续期。续期使用与控制台一致的浏览器锁名称，避免多个标签页同时旋转刷新 Cookie。写操作验证同源 Origin 和自定义请求头；服务逐次校验身份，不依赖前端显隐授权。

门户公共 API 前缀 `/portal-api/`；既有 `/api/`、`/v1/`、登录、控制台和价格页不被门户路由覆盖。New API 的 `general_setting.docs_link` 已改为 `https://shinyapi.com/docs/`，其余请求重试、审核、渠道、支付与计费设置未改。

## Markdown 导入与维护

1. 登录超级管理员后打开 `/site-admin/`，先完整刷新页面。旧编辑器保存请求会收到 409，防止覆盖新格式正文。
2. 单篇使用「导入当前正文」；多篇使用「选择多个 .md」，关联文档较多时推荐「选择文档文件夹」。README 和 `00-` 开头的导出目录文件默认跳过。
3. 导入预览可改标题、稳定 slug、分类；重复 slug 拒绝覆盖。保留原文件相对路径，用于将 `.md` 相对链接映射到已导入文章；同名文件存在歧义时不自动猜测。关联文章未导入时会提示未匹配。
4. 点击预览检查排版及外部链接/图片提示，核对本站接口、分组、价格和客服。远程图片仍引用原站，不自动抓取；需要本站持久保存时用「上传并插入图片」。
5. 「全部保存为草稿」只保存，不公开；逐篇检查后点击「发布到网站」。发布动作针对当前整个内容草稿，需一并确认其他待发布修改。
6. 页面标题、分类、标签、适用版本与正文可编辑；原始正文可导出。旧 `sections` 文章保持原阅读路径，编辑时生成包含代码、提示和关联链接的 Markdown，保存后使用 `body_markdown`/`format_version=2`，没有清空原内容库。

渲染使用本地固定版本 markdown-it 和 DOMPurify（见 `web/vendor/manifest.json` 及许可证），不依赖运行时第三方脚本 CDN。HTML 经严格白名单清理；脚本/事件属性不可执行。代码只显示和复制。正文搜索与分组目录使用已发布内容；草稿不进入公开索引。

本次升级记录：`maintenance/portal-docs-upgrade-20261016/`。生产数据摘要切换前后相同；上传与发布的写入验收在独立候选内容库完成，正式站仅做读取和页面检查。新发布保留 v5/v6 与原静态首页的资源路径，兼容旧标签页。最新源码构建命令：`python portal/build.py --release <new-id>`。

## R2 配置与上传

1. 在 Cloudflare 新建用于公开文件的 R2 桶，为其绑定 HTTPS 自定义下载域。创建仅限本桶的对象读写 S3 凭据，记录 Account ID、桶名、Access Key ID 和 Secret Access Key。
2. 打开 `/site-admin/?tab=storage`，启用 R2，填写以上字段和公开下载地址；目录前缀默认 `downloads`。保存后页面不回显密钥，空白密码框表示保留已有值，更换时须填写成对凭据。设置保存立即生效，与内容发布分开。
3. 在 Cloudflare 桶设置中配置页面提供的 CORS JSON，正式 Origin 为 `https://shinyapi.com`。直传使用签名 PUT，允许 Content-Type、Content-Disposition、x-amz-meta-portal-upload-id；不需要给所有来源通配权限。
4. 点击「检查桶及 CORS」。服务端只在随机测试路径写一个小文件、HEAD 校验并删除，并读取桶的 CORS，检查本站 Origin、PUT 和所需请求头。未配置或不完整时会明确提示；无读取桶策略权限时提示手工核对。检查不验证公开域名和本机网络，首次使用仍需实际上传下载。失败消息不包含密钥或签名URL。
5. 资源管理选择「R2 公开文件」，选择附件并保存资源草稿。默认上限 10240 MB（10 GiB，界面简写 GB），管理员可在存储设置改为 512–102400 MB；旧设置缺少字段时继承 10 GB，无须重填密钥。前端和签发接口共同限制文件大小。<=64 MB 使用单 PUT，大文件使用固定 32 MB 分片，每文件最多 2 片并行，最多自动重试 4 次并重新签发上传地址。实际文件不进入门户内存或 `/v1/`。
6. 可上传 ZIP、EXE、MSI、DMG、PKG、DEB、RPM、AppImage、7z、tar/gz/xz 及支持的文档/图片。下载响应为 attachment。对象名包含随机ID，避免覆盖已有文件；原文件名保存在下载响应元数据。

7. 新建资源支持一次选择最多20个附件，最多2个并发上传；每个文件生成一个独立资源条目。文件名中的Windows/macOS/Linux和x64/ARM64可自动识别，队列中可手动改系统与架构。不同平台复用表单中的版本、分类、简介、关联教程，资源名称追加平台与架构；发布后按平台筛选。编辑现有资源时仍只替换一个文件，新增多平台请先放弃当前编辑，再新建一批资源。
8. 部分失败时可再次保存只重试失败项，或仅保存成功项并保留剩余队列；已上传文件不会重复上传。内容草稿保存失败时保留已完成文件信息，重试草稿保存无需重复上传。队列未保存前不允许导航丢失；显式「放弃资源编辑」不会删除已写入R2的对象，清理可在桶中进行。

9. 资源保存使用独立的资源批次接口，在事务中将本次变更合并到最新草稿，不再用上传前的整个内容版本覆盖服务器。其他窗口修改首页/教程不会阻塞新增资源；相同资源同时修改时仍返回409，保留上传结果。重复提交相同资源内容可安全重试。
10. 刷新后在资源管理顶部的「已上传但尚未保存到资源库」找回本人已完成的R2上传，最多显示50项，每次可恢复20项。恢复只读取上传记录，不重传文件；填写资源信息后保存。已存在于草稿或发布资源中的URL不再列出；使用固定上传标识生成资源ID并阻止重复链接入库。

公开桶文件上传完成即可以已知地址访问，草稿仅控制资源列表是否展示。这与本地附件发布前私有的语义不同，页面有明确说明。需要私有文档时继续用本地附件；本期没有私有桶按用户鉴权下载功能。

11. 点击「暂停上传」保留分片，再次点击「保存资源草稿」继续。刷新后在「未完成的大文件上传」重新选择原文件；浏览器先核对文件元数据与采样指纹，再逐个重新读取已上传分片并校验完整 SHA256，仅传缺少的分片。浏览器不能在刷新后自动获得本地文件访问权限，因此必须重新选择。原标签页 sessionStorage 仅保留资源表单、平台、架构和替换目标，不保存文件、签名 URL 或密钥；换浏览器后需重新填写资源信息。
12. 「取消并清理」调用 R2 AbortMultipartUpload，完整文件已经合并时拒绝删除。分片合并成功且 HEAD 校验大小、MIME、上传标识后才进入「已上传但尚未保存到资源库」；用户下载仍为一个完整文件。完成响应丢失时重试会通过 HEAD 恢复，无须重传。分片 SHA256 是续传时的客户端内容校验；服务端不下载 GB 数据重新哈希。

停用R2不删除已上传文件，也不改变已发布下载链接。移除资源不会物理删除R2对象。关闭标签页保留分片；7 天后任务过期，桶通常会根据 R2 生命周期规则清理未完成分片，本站没有擅自修改桶规则。改换存储配置后旧会话拒绝继续或操作新桶，需在原桶清理。小文件单 PUT 暂停后会重新上传。

分片状态存于独立的 `r2_multipart` 与 `r2_multipart_parts` 表，保持既有 `r2_uploads` 11 列形状不变，兼容 v12 回滚；v12 不显示或处理尚未完成的新分片任务，回滚前应先暂停并记录这些任务。

真实R2服务由管理员填写凭据后首次验证。自动测试使用真实boto3 SDK与本地HTTP S3协议夹具，覆盖签名链接、直传、HEAD、取消、密钥不回显及配置持久化；不能替代真实桶权限、自定义域与网络验证。独立配置应使用受保护的服务器备份，不得纳入公开内容导出。
